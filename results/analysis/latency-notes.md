# Latency notes — which timing numbers are quotable

The numbers below are the `lat_median_s`, `lat_p95_s`, `lat_mean_s` and
`wall_time_s` columns of `results/experiments.csv`, which
`scripts/collect_results.py` computes from each run's per-query timers.

## The rule

**Quote medians and p95. Do not quote `wall_time_s` or the mean for any run flagged
`wall_clock_suspect`.**

`wall_time_s` in `*.meta.json` and `results/experiments.csv` is raw wall-clock
around the generation loop. It includes any time the machine spent asleep, so a
run that slept reports inflated latency that is not a property of the pipeline.

## The detector

A run that slept has **mean > its own p95**. A few multi-hundred-second outliers
drag the mean past the 95th percentile — physically impossible for a well-behaved
latency distribution, so this is a reliable and cheap sleep detector. It is now
computed automatically and surfaced as a `wall_clock_suspect` column by
`scripts/collect_results.py`.

### `hotpotqa_base` — the one contaminated run

69.5 s/q mean against a 39.0 s p95, and `wall_time_s` 34,745.7 s vs ~13,000 s for
every comparable tag. The machine slept mid-run despite `caffeinate -i` being the
documented policy. Its **median (26.0 s) and p95 (39.0 s) are unaffected** —
per-query timers are taken inside the loop, so only the aggregate wall-clock and
the mean absorbed the sleep.

Actions taken:
- The raw artifacts (`*.jsonl`, `*.meta.json`, `results/evaluation/*.json`) are
  **left untouched** — they are the provenance record of what actually ran.
  Falsifying them would be worse than annotating them.
- `results/indexing/scaleup-log.md`'s 4-tag table carries an inline warning on that cell.
- The paper's `tab-systems` (generated by `scripts/make_tables.py`) is built from
  medians and omits the contaminated aggregate entirely.

### `2wikimultihop_base` is NOT contaminated

39.5 s mean vs 58.6 s p95 — mean below p95, so the distribution is well-behaved.
It is genuinely slower than the other tags because compression is off and 2Wiki
contexts are long. This one is real and quotable, and it is the source of the
"compression cuts median latency 27%" claim (34.6 s -> 25.3 s).
